## v0.6.2：分身二次伤害修复 + 连击卡住修复

### 根因（Player.log 铁证 + 反编译确认）
- RL2 的攻击伤害由**内嵌在 Animator Controller 资产里的 StateMachineBehaviour** 触发：`EffectTriggerAnimBehaviour`（[SharedBetweenAnimators]，字段 EffectTriggerEntry[]）在 OnStateEnter/OnStateUpdate 里调 `EffectTrigger.InvokeTrigger` 生成伤害/特效。
- 克隆体共享同一 controller → 分身播攻击动画时也在分身位置生成攻击判定 → **怪物吃两次伤害**。
- 克隆体上被剥离的脚本导致 `BaseCharacterController.get_EffectVelocity` NRE 刷屏（日志 4458 行起大量）。
- 反编译存档：/d/RL-Mod/decomp/EffectTriggerAnimBehaviour.cs、EffectManager.cs。

### 修复：游戏自带 per-animator 效果禁用开关（不能用 DISABLE_GLOBALLY，会误伤本地玩家）
- `EffectManager.AnimatorEffectsDisabled(animator)` 检查 `m_globalEffectDisableList`（HashSet<Animator>）。
- API：`EffectManager.AddAnimatorToDisableList(Animator)` / `RemoveAnimatorFromDisableList(Animator)`；`EffectManager.IsInitialized` 守卫。
- RemoteAnimatorMirror.Update 每秒重申一次把所有克隆体 Animator 加进禁用列表（防场景切换清空）。动画播放不受影响，特效视觉由粒子镜像补上；EffectTrigger 生成的伤害/投射物不再在分身位置出现。

### 修复：连击卡住（连续攻击武器）
- 根因：克隆体一次性状态播完后 normalizedTime 停在 1.0（小数部分归 0），本地连击重开的时间回卷检测（tgtF < curF）永远不成立 → 卡最后一帧。
- 修复：加"cloneFinished（curN>=0.99）且本地还在播（tgtN<0.99）→ 立即 Play 对齐"；本地中途重开阈值从 0.4 收紧到 0.05。ApplyNetworkAnim 同步加同样规则。

## v0.9.4（18:35 部署 99328 字节）：修真机联机三大问题

用户反馈：连上了但画面没对方角色、地图不一样、客机显示 CLIENT ID=0。

1. **CLIENT ID=0（根因）**：host 用 `peer.Id` 当玩家 ID，而 LiteNetLib 给第一个连上来的 peer 分配的 Id 就是 0，撞了硬编码的 `HostId=0`。双方都认为玩家列表只有自己（id=0）→ 所有 PlayerState 被 `id == LocalPlayerId` 判成回声丢弃 → 画面里永远没有对方。
   修复：改用自增 `_nextPlayerId`（从 1 起，0 永久保留给主机）+ `_peerToPlayerId` 反查表（断开连接/转发排除发送者用）。
2. **地图不一致**：客机是"先自己开一局再连进来"，首次收到 seed 时 `_clientSeedOverride` 还是 -1，旧的重进判断（只在种子变化时触发）不成立 → 客机留着自己那套地图。
   修复：`OnClientReceivedSeed` 新增 `ReadCurrentEffectiveSeed()`——直接比对"客机当前世界实际生效的种子"与主机种子，不一致就返回 true 触发重进。
3. **转场中放弃重进**：原来 `SceneLoader_RL.IsLoading` 时直接 yield break，种子不会重复下发就永远对不齐。改成最多重试 10 秒。
4. 顺手降噪：`GetCurrentSeed returned -1` 每帧刷 → 改 1 秒轮询；`[STATE] captured` 每帧刷 → 独立 10 秒节流。

关键教训：**LiteNetLib 的 NetPeer.Id 不能直接当游戏内玩家 ID 用**（服务端第一个 peer 的 Id = 0）。

## v1.0.0（19:03 部署 114176 字节）：地图整块同步 + 角色外观同步

用户反馈三问题：地图仍不同、主机看客机白块、客机看主机是自己的样子。

### 地图问题的真正根因（重要发现）
RL2 地图**不是**每次用种子重新生成，而是**存在存档 StageSaveData 里**：
- `LevelManager_RL` 进 World 时 `LoadStageSaveData(profile)` → `SaveManager.LoadGameData(profile, Stage, out data)` 从磁盘读 → `WorldBuilder.CreateWorld(data)`
- 只有"新建世界"分支才用 RNGManager 从 MasterSeed 派生 BiomeCreationSeed/MergeRoomSeed/PropSeed/EnemySeed
- 所以种子对上也没用，客机照样用自己存档里的旧地图

### 实现 MapSync.cs
- HOST：`SaveManager.StageSaveData` 用 BinaryFormatter 序列化 → 分块（16KB）发（MsgType.MapData=17，每个客机只推一次，靠 `_sentTo` 集合）
- CLIENT：重组 → 反序列化 → 备份原对象 → 替换 `SaveManager.StageSaveData` → 2 秒后 LoadScene(World)
- **关键补丁**：postfix `SaveManager.LoadGameData(int, SaveDataType, out object)` —— saveType==Stage 时把输出换成主机 StageSaveData，否则磁盘读档会把替换冲掉
- 存档保护：CreateSaveFile 序列化 StageSaveData 时临时换回客机原对象
- 会话结束 Restore

### 实现 CharacterSync.cs
根因：整树克隆模板永远来自**本地玩家** → 客机看主机=自己的样子，主机看客机=自己的装备。
- 传输 `PlayerSaveData.CurrentCharacter`（CharacterData，[Serializable]，含职业/装备/性别/肤色/发型/五官/特质）
- 客机/主机互相发送（MsgType.CharacterData=18，带 playerId；主机转发给其他客机）
- 应用：`LookCreator.InitializeClassLook` + `InitializeCharacterLook` + `InitializeHelmetLook/ArmorLook/CapeLook/WeaponLook`（只操作 SkinnedMeshRenderer，不依赖 PlayerController）
- **StripClone 必须保留 LookController**（它的 geo 引用是 SerializeField），但 SetActive 前 `enabled=false`（阻止 PlayerLookController.Start 等 m_playerController 的 NRE）
- 本地角色变化（换继承人/换装）3 秒轮询对比签名自动补发

## v1.0.1：分身"看不到对方" + 累赘数量不一致

### 问题 1：客机看不到主机（偶发，且客机必现）
日志证据（客机）：地图同步后强制重进 World → 状态包先到 → `CreateRemotePlayerObject` 里
`GetVisualCloneTemplate()` 返回 null（`CachedLocalPlayerObject` 还是空）→ 退化成
"fallback 白块"（sortingOrder 很低，被背景遮住）= 玩家眼里"对方不见了"。
之后没有任何重试路径（RemotePlayers 里已有条目，不会再进创建分支），所以永久是白块。

修复（PlayerSync.cs）：
- 抽出 `AttachCloneVisual(id, go, template)`：挂 "Visual" 子物体 + 外观 + 动画镜像，幂等
- 新增 `TryUpgradeFallbackVisuals()`：每 0.5s 扫描"没有 Visual 子物体"的分身，本地玩家一出现就升级
- `RefreshRemoteAppearance` 里若发现还是白块，收到外观包时立刻顺带升级
- 升级时把 `RemotePlayerInterpolator.SetVisualScale(1f)`（新增），否则翻面基准沿用白块的 0.77，x=0.77/y=1 会被压扁

### 问题 2：主机 24 个累赘，客机 12 个
根因不是"没解锁"这么模糊：`BurdenManager.GetBurdenLevel` 内部有一句
`if (... && IsBurdenUnlocked(type)) return burden.CurrentLevel; return 0;`
而 `IsBurdenUnlocked` 对 CastleBossUp/BridgeBossUp/ForestBossUp…CaveBiomeUp 共 13 种
看的是 `PlayerSaveData.HighestNGPlusBeaten`。主机 NG+9 解锁齐 → 读得到；客机 HighestNGPlusBeaten 低 → 全读成 0。
NG+ 界面的 `NewGamePlusOmniUIEntry.IsEntryActive => IsBurdenUnlocked`，锁着的显示 "???"，所以看起来"少一半"。

修复（RaceMode.cs / NetworkManager.cs，协议 MSG_RaceRules 加一个 int）：
- 广播 `HighestNGPlusBeaten`（原来只有 NewGamePlusLevel）
- 采集累赘改用 `BurdenObj.CurrentLevel` 绕开解锁过滤（`ReadBurdenLevelRaw`）
- 应用时 `PlayerSaveData.HighestNGPlusBeaten = host` 先解锁门槛，再对全部 26 种 `BurdenObj.ForceLevel(host值或0)`
  —— 用 ForceLevel 而不是 SetBurdenLevel，因为 GetBurdenStatGain/GetBurdenWeight 也查解锁，只写等级不生效
- 备份/恢复/存档保护（RestoreForSave / ReapplyAfterSave）都带上 HighestNGPlusBeaten 与全量累赘
- 首次应用后打一条"生效复核"日志：用 GetBurdenLevel 统计项数/总等级，和主机对比即可验证

### 补充（同一次修复里发现的隐藏坑）：进世界会换掉 PlayerSaveData
`SaveManager.LoadGameDataAndUpdate(profile, SaveDataType.Player)` 直接把
`PlayerSaveData = loadDataOutput as PlayerSaveData` —— 整个对象换新，内存里的规则覆写全丢。
客机套完规则后 MapSync 又强制重进 World → 一读档就退回自己的 NG+/累赘（12 个）。
修法：postfix `SaveManager.LoadGameDataAndUpdate(int, SaveDataType)`，当 Applied && saveType==Player
时调用 `RaceRulesSync.ReapplyAfterSave()` 把主机规则重新写上新对象（磁盘永远只有真值，所以不用重备份）。

## v1.1.0：赛事沙盒世界（Sandbox.cs）

需求：不碰存档生成一个纯净世界，参数由房主定（周目/累赘档位/技能全满/装备全解锁），双方进去比，打完销毁，下次重新生成。

### 核心机制（反编译确认）
- 平时地图来自存档：`LevelManager_RL.BuildWorldCoroutine` → `LoadStageSaveData` → `LoadGameData` → `WorldBuilder.CreateWorld(stageSaveData)`。
- **程序生成入口**：`WorldBuilder.CreateWorld()`（无参重载）= 不带存档数据 = 用 RNGManager 现场生成。
- 世界建完后（`WorldBuilder.State == Complete`）房间坐标/种子都在 GridPointManager 里，
  用游戏自己的 `StageSaveData.CreateEmptyRoomSaveDataList()` 就能从**当前世界**反推一份完整 StageSaveData。
- 这份"沙盒地图"交给现有 MapSync 推给客机 → 客机照常重建同一张图（不依赖种子确定性，最稳）。
- 纯净：4 个 tracker 列表（Enemy/Chest/Item/Room）都给空 List，所以没有开过的宝箱和 Boss 标记。

### 补丁
- `WorldBuilder.CreateWorld(StageSaveData)` prefix：沙盒时 `Sandbox.BeginFreshGeneration()`（按沙盒种子初始化 RNG）+ `WorldBuilder.CreateWorld()`，跳过读档。
- `SeedSync.InitializeRngPrefix` 扩展：`Sandbox.WantsFreshWorld && IsHostSandbox` 时强制 MasterSeed（覆盖"局内重建"分支）。
- `RaceRulesSync.ApplyLocal`（原 ApplyHostRules 的实现）主客机通用；沙盒用它写周目/累赘。
- `SaveManager.CreateSaveFile` prefix/postfix 增加 `Sandbox.RestoreForSave/ReapplyAfterSave`：写盘时把 StageSaveData 换回玩家自己的、装备/技能换回真值。
- `LoadGameDataAndUpdate` postfix 增加 Equipment 分支 → `Sandbox.OnEquipmentReloaded()`。

### 生命周期
- `PrepOnly()`：只应用规则（方便先在城里铁匠铺配装，因为 RL2 只能在城里换装备），等 WorldLive=false。
- `HostStart()`：WorldLive=true → 挂起 MapSync 推送 → 重进 World 现场生成 → 抓图 → 解挂推送。（60 秒超时兜底）
- `HostDestroyAndReload()` / Race 结束（nm.Stop → Sandbox.Stop(reloadWorld:true)）：还原规则/技能/装备/StageSaveData，2 秒后重进 World 回到自己的存档。
- 协议 `MsgType.SandboxConfig=19`：ngPlus / burdenLevel / flags(技能|装备) / seed。新客机连接时补发。

### 注意
- 技能树"全满"只到 `SkillTreeObj.MaxLevel`，且技能主要是解锁类；当前继承人的血量/伤害是出生时算的，不会变。
- 装备全解锁 = 把 5 个字典的 UpgradeLevel 顶到 MaxLevel（FoundState=Purchased，铁匠铺免费换）。
