## v2.8.6：卡房间回退 + 自定义名字 + 死亡模型 + 观战房间定位

用户在 v2.8.5 上报告四件事：①两端同时极其严重卡房间；②控制面板要能自定义玩家名字；

只读调研 decomp/full + 源码后做以下修复，协议 3000 不变。

### 1. 卡房间：回退 v2.8.5 唯一的全局改动
调研结论：`PauseCompat` 的 prefix 从"只拦 TimeScaleType.Game"放开到"拦所有 value<=0"
会拦掉 `BaseAIScript.DeathAnim` 的 `SetTimeScale(Cutscene, 0f)`（Boss 死亡定格，
两端同时、每次 Boss 死都发生）——这是 v2.8.5 唯一每次调用都触发的全局时序改动，
与"两端同时"特征吻合。`SceneChangeSync` 的 Reset() 只在看门狗重试路径触发，
正常转场不触发，不是日常卡房间根因。
**改动**：`PauseCompat.cs` 恢复 `timeScaleType == TimeScaleType.Game && value <= 0f`。
Cutscene 残留 0 仍由看门狗 `RLTimeScale.Reset()` 兜底。
**注意**：无用户日志，不能 100% 确认根因。若仍卡，需日志中 `[SCENE]`/`[ROOMSYNC] 跟随超时放弃`/
`[ROOM] .../门触发器` 三类标记进一步定位。

### 2. 控制面板自定义玩家名字（新功能）

### 3. 死亡方尸体跟着活人动
根因：对端倒地后动画包变空 → `RemoteAnimatorMirror.Update` 因
`TargetLayerHashes.Length==0` 走 `MirrorAnimator()` 兜底，逐帧拿**本机存活玩家**的
Animator 状态往尸体上套；`MirrorFx` 同理套粒子。原 `ApplyDownedVisual` 只 freeze 位置、
停 Animator.speed 和粒子，但镜像层每帧又把它们改回来。
**改动**（`PlayerSync.cs`）：`RemotePlayerInterpolator` 加 `internal bool Downed`；
`ApplyDownedVisual` 写入该标志；`RemoteAnimatorMirror.Update` 在禁用 EffectTrigger 后、
镜像前 `if (_interp.Downed) return;`；`HandleRemoteAnim` 源头也挡掉 `RemoteDowned.Contains(id)`。
活人分身 Downed=false 完全不受影响，复活后自动恢复。不对分身 SetActive(false)（复活/救援/仇恨依赖它存在）。

### 4. 观战看不到未探索房间
根因：`EnemyAliveSync.HostRoomCoords` 只在**客机端**计算（主机广播、客机接收），
所以主机倒地观战客机时它恒无效 → `EnsureSpectateRoom` 只能拿分身坐标 +
`FindRoomContaining` 的 bestActive 偏好，锁在旧的已激活房间；同时
`RoomTravelSync.ApplyNow` 在 LocalDown 时 Drop 换房应用，不激活新房间。
房间对象其实全量预生成（`WorldBuilder`→`InstantiateRooms_BuildStage`），缺的是**激活+定位**。
**改动**：`RoomTravelSync.ApplyTravel` 无论是否倒地都记录 `HasRemoteRoom/RemoteRoomCoords/
RemoteRoomLanding`（权威换房包坐标）；`Downed.Tick` 观战定位优先用它们，再回退 HostRoomCoords/
怪平均坐标。保留现有激活段（种子/刷怪/背景/存档/相机），未换成 CompleteRoomActivation 以控风险。
