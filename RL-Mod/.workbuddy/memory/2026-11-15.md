# 2026-11-15

## RL-Mod（Rogue Legacy 2 BepInEx 联机 mod）排查：面板不显示

**根因**：`LiteNetLib.dll` 用的是 .NET Standard 2.0 版本，依赖 `netstandard, Version=2.0.0.0`。
RL2（Unity 2020.3.22，Mono）的 `Rogue Legacy 2_Data/Managed` 里没有 netstandard.dll，于是：
- `AddComponent<NetworkManager>()` 失败：`The script 'RL2Multiplayer.NetworkManager' could not be instantiated!`
- 任何访问 NetworkManager 的类型/字段都抛 `BadImageFormatException: Could not resolve field token ... NetworkManager:_netManager`
- `DrawWindow()` 第一行 `GetStatusText()` 就抛异常 → `GUILayout.Window` 每帧中断 → 面板永远不出现
- 异常在 `Plugin.Awake` 中穿透 → 启动阶段对象被销毁（日志里的 `=== Plugin OnDestroy ===` 是启动时销毁，不是退出）

**关键教训**：BepInEx 的 `LogOutput.log` 里没有这条错误，错误只出现在 Unity 的
`%USERPROFILE%\AppData\LocalLow\Cellar Door Games\Rogue Legacy 2\Player.log`。以后 mod 报错先看 Player.log。

**修复**：LiteNetLib 换成 net471 构建（NuGet litenetlib 1.2.0 的 `lib/net471/LiteNetLib.dll`，版本号相同只换 TFM），
依赖变为 mscorlib/System/System.Core/System.Runtime.Serialization，RL2 环境可解析。
- `RL-Mod/Libs/LiteNetLib.dll` 已替换，原文件备份在 `RL-Mod/Libs/_backup/LiteNetLib.netstandard2.0.dll`
- 游戏 `BepInEx/plugins/` 已部署新 RL-Mod.dll + LiteNetLib.dll，旧文件备份在 `plugins/_backup_1611/`

**代码加固**（Plugin.cs）：OnGUI 全包 try/catch 并把异常画在屏幕上（`RL2MP GUI ERROR`）；
重置 `GUI.matrix/color/depth`；GUIStyle 缓存；按钮前加 `NetworkManager.Instance != null`；新增 F7 作为 Keypad1 备用开关。

## RL2 联机架构调研（地图生成 + 死亡循环）

**游戏自带的确定性生成机制**（反编译 Assembly-CSharp 得到，可直接用）：
- `RNGSeedManager`（ScriptableObject）：`m_sceneToCurrentSeedTable`（场景名→种子），静态属性
  `MasterSeedOverride`、`TempSeed`、`ProjectSeed`，方法 `SetMasterSeedOverride(int)` /
  `SetTempSeed(string)` / `GenerateNewSeed(string)` / `GetCurrentSeed(string)` /
  `GetSeedAsHex(int)` / `ClearOverride()`。
- `GenerateNewSeed` 取值优先级：TempSeed > ProjectSeed > MasterSeedOverride（**仅 World 场景**）> `Environment.TickCount`。
- `RNGManager`：`Reset(int)`、`InitializeRandomNumberGenerators(int)`、`SetSeed(RngID,int)`、`GetSeed(RngID)`。
  `RngID` 共 16 项：BiomeCreation=10 Chest=20 Enemy=30 Lineage=40 Prop=50 SpecialRoomProps=60
  MergeRooms=70 Room_RNGSeed=80 Room_RNGSeed_Generator=81 Prop_RoomSeed=90 Deco_RoomSeed=100
  Enemy_RoomSeed=110 Chest_RoomSeed=120 SpecialProps_RoomSeed=130 Hazards_RoomSeed=140 Tunnel_RoomSeed=150。
- **正确注入点**：`RNGSeedManager.GenerateNewSeed` 的 Harmony Prefix，`sceneName=="World"` 时
  `SetMasterSeedOverride(seed)`。所有进城堡路径都走这里。
- 坑：`RNGSeedManager.OnSceneLoaded` 会 `ClearOverride()`（清空三个种子），所以不能提前设一次。
  现有 `NetworkManager.ApplyMasterSeedOverride` 在 World 建好后再 `InitializeRandomNumberGenerators` 是**无效**的。

**存档结构**：`SaveManager` 全是 static —— `PlayerSaveData`（含 `MasterSeed`/`PreviousMasterSeed`/
`IsDead`/`InHubTown`/`InCastle`/`GoldCollected`/`CurrentCharacter`）、`StageSaveData`（含
`BiomeCreationSeed`/`MergeRoomSeed`/`EnemySeed`/`PropSeed`/`RoomSaveDataDict`/`ForceResetWorld`）、
`LineageSaveData`、`EquipmentSaveData`、`ModeSaveData`；有 `DisableSaving` 开关。

**开源参考**：
- `rain-on-roof/rl2-coop`（MIT）——最贴合。`src/RL2Coop.Plugin/RL2/Hooks.cs` 仅 145 行，内含
  `SharedSeed`（GenerateNewSeed prefix）、`LocalDeath`（KillCharacter prefix 做倒地+观战）、
  `GuestEnemyDeath`、`NoPauseOnFocusLoss`；`RL2World.cs` 做房间跟随 / `FindRoom(roomId)` / 分叉检测；
  `src/RL2Coop.Net/Sync/` 有 SnapshotBuffer/Interp/ClockSync/EnemyMirror/Spectator。
- `mcrib884/rl2coop`——CoopDownedManager、PlayerDeathWindowControllerCoopAutoLineagePatch、EnemySyncController。
- `RL2-API/RL2.API`、`RL2.ModLoader`（社区 modding API）、`zaphim12/RL2Archipelago`（随机化）。

**分身显示成攻击特效 + 镜头波动（v0.4.1 修复）**：
- 根因1：分身贴图每 0.1s 从"本地玩家当前激活的任意 renderer"抄 → 抄到的是武器挥砍/特效层（RL2 玩家随时激活的往往不是身体层）→ 分身变成闪烁的攻击特效。
- 根因2：debug sim 用 sin 双轴绕本地玩家转圈 → 观战镜头跟着分身画圆 → "视角一直波动"。
- 修复：外观捕获改为**选面积最大的 sprite**（身体层永远最大）并缓存该 renderer，动画帧只从这个 renderer 同步；debug sim 改为 PingPong 左右巡逻、贴地(y offset=0)、朝向按与上一帧位置差判断（`_debugFakeLastX` 字典）。
- 镜头补充确认：游戏只在切房间(`CameraController.OnPlayerEnterRoom`)/过场时调 `SetFollowTarget`，不是每帧竞争，无需 patch。

**角色渲染结构（dump 确认，v0.4.2）**：RL2 玩家是 **SkinnedMeshRenderer 骨骼网格**，
层级 `Player/Pivot/Visuals/Player_ModelVariant`：geo* 全是 SkinnedMeshR（身体/眼睛/武器/职业套装），
`root/main/waist/hips/spine...` 是骨骼树，Player 根上有 Animator 驱动。SpriteRenderer 只有武器挥砍特效。
→ 分身外观唯一正确做法：**整树克隆**（先 SetActive(false) 原体防止克隆体脚本 Awake 抢单例 → Instantiate →
StripClone 只留 Transform/Animator/MeshFilter/MeshR/SkinnedMeshR/ParticleSystem(+Renderer)，DestroyImmediate）→
模板存 DontDestroyOnLoad，每个分身 Instantiate 一份挂到 RemotePlayer 下。dump 工具：小键盘6 / 面板按钮。
构建注意：Libs 需补 UnityEngine.AnimationModule.dll / UnityEngine.ParticleSystemModule.dll（从游戏 Managed 拷）。

**联机设计结论**：地图走"种子一致"，死亡走"房主权威 + 倒地观战 + 全员倒下才真死"，回城阶段一起回，
客人 `DisableSaving`，HubTown 跳过同步。

## v0.4.0 落地：倒地观战（Downed.cs）

**游戏侧关键 API（反编译确认）**：
- `BaseCharacterController.KillCharacter(GameObject killer, bool broadcastEvent)` —— 只有 4 条 IL：
  `IsDead=true` / `StopAllStatusEffects(false)` / `ConditionState=6`。**PlayerController 没有重写**，
  所以 patch 基类即可拦住玩家死亡；敌人走 `EnemyController.KillCharacter` 重写不受影响。
- 死亡界面真正的推进入口是 `PlayerManagement_RL.PlayerDeathToLineage_SceneTransition`（靠 IsDead 触发），
  所以把 IsDead 拦住 + 角色 `SetActive(false)` 就完全不会进死亡流程。
- **镜头**：`CinemachineVirtualCameraManager.SetFollowTarget(Transform)`（public），
  另有 `IsActiveVirtualCamera` / `SetIsActiveCamera(bool)`。全局用
  `Resources.FindObjectsOfTypeAll` 找实例（`gameObject.scene.IsValid()` 过滤资源）。
  `CameraController` 里还持有 `CinemachineBrain`，但跟随是 vcam 层的。

**实现**（D:\RL-Mod\RL-Mod\Downed.cs，约 380 行）：
- `DownedState`（全静态，不依赖 GameObject 存活）：`LocalDown` / `AllowRealDeath` /
  `SpectateTargetId` / `LastAlivePos`；`GoDown` / `Revive` / `TriggerRealDeath` / `CycleTarget`
  / `AliveRemoteCount` / `Tick`。
- `DownedPatches.Apply(harmony)` 手动打 `KillCharacter` prefix：`__instance is PlayerController`
  且 `InSession` 且非 `AllowRealDeath` 时才拦截。
- `DownedManager`（挂 RL2MP_Runtime）：每帧 `Tick`、`[`/`]` 切换观战目标、sceneLoaded 重置。
- 协议扩展：`PlayerStateData.Downed` + PlayerState 包尾部多 1 字节（host 转发同步扩展）。

## 第二轮：LiteNetLib 修好了，但面板仍不显示

日志显示 `NetworkManager.Awake()` / `PlayerSync.Awake()` 都正常了，说明 netstandard 问题已解决。
但 `Chainloader startup complete` 之后立刻 `Plugin.OnDestroy`，随后才 `UnloadTime` → `Loading Rogue Legacy 2`。

**根因**：RL2 的启动链是 `OnGameLoadManager.Run()` → `Application..cctor()` → `BepInEx Chainloader`，
也就是插件 Awake 发生在 **Application 静态构造期间**（引擎还没初始化完 SceneManager）。
此时创建的对象（包括 BepInEx_Manager 和我们的 NetworkRoot）**DontDestroyOnLoad 无效**，
启动流程末尾统一卸载场景时全被销毁 → 插件组件连同 OnGUI 一起没了 → 面板永远画不出来。

**架构调整（v0.3.0）**：
- `Plugin` 只负责配置 + Harmony + 挂**静态**回调（`SceneManager.sceneLoaded`、`Application.onBeforeRender`、`Application.quitting`），
  这些回调不依赖任何 GameObject 存活。
- `Bootstrap`（静态类）负责 `Ensure()` 创建运行时对象，触发点有三处：场景加载、`OnGameLoadManager.Run` postfix、1 秒节流看门狗。
  创建的对象一律 `DontDestroyOnLoad`，此时引擎已就绪，DDOL 才真正生效。
- UI 从 Plugin 搬到新文件 `ControlPanel.cs`（MonoBehaviour，挂在 RL2MP_Runtime 上）。
- Plugin.OnDestroy 里**不再 UnpatchSelf / 清理**（因为它在启动阶段就会被调用），清理改到 `Application.quitting`。

**坑**：备份目录不能放在 `BepInEx/plugins/` 里面，BepInEx 会递归扫描 → 日志出现
`2 plugins to load` + `Skipping ... because a newer version exists`。备份已移到 `BepInEx/_backup_1611/`。

## 第三轮：面板已正常；远程玩家外观问题（v0.3.1）

现象：加模拟玩家只出现一个白块，转一下就消失。

原因有三：
1. **白块**：`CreateRemoteSprite()` 只接受 `gameObject.activeInHierarchy == true` 的 SpriteRenderer，
   而 RL2 玩家身上 4 个 renderer 全部 inactive（分层 sprite，平时禁用）→ 永远走 fallback 白块。
2. **消失（被挡）**：`sr.sortingOrder = 5` 硬编码，低于场景/玩家的排序值 → 被墙和装饰物挡住。
3. **"转一下"**：`RemotePlayerInterpolator` 用 `Mathf.Lerp` 把 scale.x 从 +1 过渡到 -1，中途经过 0（宽度为零），
   看起来就是原地转一圈然后消失。

修法：`TryCaptureVisualSource()` 缓存本地玩家的 sprite / lossyScale / sortingLayerID / sortingOrder / z（不再要求 active），
远程对象 `sortingOrder = 源 + 1`；插值器改为直接翻符号；新增 `UpdateRemoteSprites()` 10Hz 跟随本地玩家当前动画帧。
