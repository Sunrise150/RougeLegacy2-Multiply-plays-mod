# 2026-11-20

## v2.4.0（00:12–00:45）删除扶起 + 死亡改观战 + 抽搐第二次根治 + 掉出误判

**用户反馈（原话拆解）**
1. `你怎么给我传送到房间中心位置去了` —— 换房落点跑到房间中部。
2. `客机和主机的画面还是不同步，客机一直在抽搐`。
3. `当主机被杀死的时候，怪物一直围绕在主机旁边，在客机的画面里就是怪物在抽搐`。
4. `死亡的位置是固定的，如果人物在天空中被杀死的话，那人物的尸体就会停在空中，难以救援`。
5. `将扶起功能删掉吧`。
6. `如果能实现观战的话就不用将人踢出，观战一定要能看到怪物还有人类的操作，不要出现画面不满、画面抽搐等各种问题`。

**证据（两端均 v2.3.2，00:08 那次运行）**
```
[ROOM] 玩家掉出房间 '1*Transition*'（7.5,25.0），已救回到地面 32.0,11.1
[ROOM] 玩家掉出房间 '2*Standard*'（63.4,7.0），已救回到地面 80.0,11.1
[ROOM] 玩家掉出房间 '2*Standard*'（75.7,12.2），已救回到地面 80.0,11.1
[ROOM] 玩家掉出房间 '3*Standard*'（107.8,14.6），已救回到地面 112.0,11.1
[ROOMSYNC] 广播换房 -> 房间(64,0) 落点(80.0,11.1) 门 side=2 num=0 seq=1 via=postfix
[EPOS] 客机统计: fps=326.3 活怪=0 已同步=0 权威条目=3
[EPOS] 客机统计: fps=94.2  活怪=7 已同步=7（兜底 0） 权威条目=7
```

**根因 1：换房落点 = 房间中心，是 RoomFix 的"掉虚空"误判把主机搬走的**
`RoomFix.TickInner` 的掉出判定除了 `belowFloor`，还有一条 `noGround`：
「脚下 6m 内 `TrySampleGround` 无地面 && `ControllerCorgi.Velocity.y < -1`」。
玩家**跳跃、从高台落下、站在单向平台/门口**全都满足 → 正常走路被判定掉虚空
→ `RescueFromVoid` 第 2 候选是房间中心 → 人被搬到房间中部。
而 `RoomTravelSync` 的 postfix 广播的落点就是**主机自己的实际落点**（80.0,11.1），
客机跟着到同一个点 → 用户看到"被传送到房间中心"。

**修法**
- 删掉整条 `noGround` 判定，只保留 `pos.y < Bounds.min.y - 3f`（真掉到房间底部以下）。
  横向出界完全不管（那是过门逻辑的事）。
- `TryFindSafeSpot` 候选顺序改回**门内侧优先**（用户要求"回入口"），
  其次"保持当前水平位置找地面"，最后房间中心 / 房间根。
  （误判源删掉后，触发救援就一定是真掉下去，回入口最符合直觉。）

**根因 2：客机抽搐 = 位置同步的"双模式"和本地 AI 对冲**
`EnemyPositionSync.ClientApplyLate` 对"在追本地玩家"的怪（`en.Target == TargetRemote`）
**放任本地 AI 完全主导**，只在偏差 >2.2m 时硬拉一次；偏差小时 `en.HasRendered = false`
重置渲染基准。于是本地 AI 每帧移动、同步逻辑每帧拉回，两种力互相抵消 = 抽搐。
两端 AI 的目标本来就不保证一致，尤其是主机死后（主机端怪围尸体、客机端怪追活人）。

**修法**
- 去掉双模式：**所有**怪物一律按主机权威轨迹渲染。首次同步直接吸附（避免"飞过去"），
  之后 `dt*30` 低通滤抖。AI 只负责动画/攻击判定，不再参与位置。
- 删掉 `FarCorrect` 常量。

**根因 3：主机死后怪围着尸体抽搐 —— 三处叠加**
1. `EnemyPositionSync.GetLocalPlayerPos` 不看死亡状态，主机死后仍返回尸体坐标 →
   广播的仇恨目标仍是"追主机"。
2. `EnemyAiFix.Tick` 在本地玩家 `!activeInHierarchy` 时直接 return →
   主机端的怪（权威端！）Target 永远指着已隐藏的玩家，围着尸体打转。
3. `DownedState.Tick` 每 2 秒 `ClearEnemyAggro()`（旧设计：防怪对尸体输出）→
   刚转给队友的仇恨又被清空 → 怪发呆 → 重新锁定 → 循环抽搐。

**修法**
- `GetLocalPlayerPos`：`DownedState.LocalDown` 或对象 inactive 时返回 `Vector3.zero`
  → `hasSelf = false` → 主机端广播的仇恨自动转向活着的客机。
- `EnemyAiFix` 新增分支：本地玩家死亡/观战时，把「Target == 本地玩家 or null」的怪
  改指向第一个活着的远程分身（`PickAliveRemote`）。只改原本锁本地玩家的，不碰 BOSS。
- 删掉观战期间的定期 `ClearEnemyAggro`（只在 GoDown / 复活保护窗里做一次）。
- 复活保护窗那段加 `!LocalDown` 前置，避免观战时提前 return 跳过镜头维护。

**根因 4：尸体悬空**
分身 `RemotePlayerInterpolator` 在 `freeze=true` 时直接冻结位置；人死在空中尸体就浮在那里。
另外 `HandleRemotePos` 每个位置包都 `SetTarget(..., freeze=false)`，把冻结的尸体又解冻挪走。

**修法**
- `HandleRemotePos`：`RemoteDowned` 的 id 直接 return（尸体不再跟随位置包）。
- `RemotePlayerInterpolator` 新增 `TickCorpseFall`：倒下时开始自由落体（重力 45，上限 -30），
  脚下 1m 有非触发器碰撞体就停；最多落 3 秒（防掉出世界）。

**需求 5+6：删除扶起，改成观战**
`CoOpRescue` 整文件重写：
- 删除：长按 H 救援（`TickRescuer`）、自救窗口（`IsSafeWindow` / `SafeWindowSeconds`）、
  绝对兜底、血上限惩罚（`ActualMaxHealthPostfix` / `HealthPenaltyStacks`）、
  `OnRescueReceived` / `OnRescueBroadcast` 的实际逻辑。
- 保留 API 形状（`RescueProgress` / `RescueTargetId` / `SafeCondition` /
  `SelfRescueRemaining` / `PenaltyRatio` 恒为"无救援"值），HUD 只需改文案。
- `OnLocalDown` -> `DownedState.GoDown`（隐藏角色 + 广播 downed + 镜头切队友）。
- `Tick` 只做两件事：断线 2 秒后退出观战；`CheckAllDown`（全员倒下 1.5s → 结束本局）。
- `DownedManager.Update`：删掉 `if (CoOpRescue.LocalDown) return;`，
  否则协作观战时 `[ ]` 切换目标失效（旧版协作是"待救"，镜头钉在尸体上，不需要切换）。
- `RaceMode.DrawCoOpStatus` 文案改成"你已倒下 · 观战中（[ ] 切换目标）"。

**观战加强（`EnsureSpectateRoom`）**
旧版把 `room.SaveController.OnPlayerEnter_LoadStageData()` 和相机设置写在**同一个 try** 里，
而前者在客机端必抛 NRE（房间半初始化）→ 异常一抛，相机的 confiner 就没切
→ 画面被锁在本地玩家房间边界（用户说的"画面不满"）。
- 拆成独立 try，LoadStageData 失败只打日志，不影响相机。
- 相机 confiner 只在房间变化时设一次（定期重设会让画面每 2 秒抖一下）。

## v2.4.1 客机死亡后卡死（全员倒下判定分叉 + 真实死亡触发失败）

**现象**（主机 `D:/Rogue.Legacy.2testing`，客机 `H:/RougeLegacytransform`）
- 主机先死（观战客机，`aliveRemote=1/1` 一直不变）。
- 客机随后死，1.5 秒后判"全员倒下"，打印
  `[DOWN] 放行真实死亡：AllowRealDeath=true`，紧接着
  `[DOWN] trigger real death failed: Exception has been thrown by the target of an invocation.`
- 之后画面还活着（fps 300+、心跳正常、HUB 能开关），但角色不能动也不能回城 —— **卡死**。
- 主机侧直到客机强退都是 `aliveRemote=1/1`：**从未收到客机的 downed**。

**两个根因**
1. `DownedState.TriggerRealDeath()` 的 catch 里直接 `LocalDown = false`，
   把唯一的接管通道关掉；死亡窗口没打开 → 既没死也观战不了，永久卡住。
   而且只打 `ex.Message`，`TargetInvocationException` 的真实内层异常被吞掉，查不出原因。
2. 全灭判定是**两端各自判**。主机没收到客机 downed（旧版 downed 标志挂在位置包上，
   位置包前置条件含 `PlayerSync.LocalPlayer != null`，死亡瞬间角色被 `SetActive(false)`），
   于是主机一直以为客机活着 → 不结束；客机自己判了全灭 → 单方面真死 → 两端分叉。

**修复**
- `MsgType.PlayerDown = 45`：0.3s 独立心跳，只依赖 `LocalPlayerId`，
  完全脱离位置包与本地角色引用；`GoDown`/`Revive` 另外即时补发一次。
- `MsgType.RunOver = 46`：任一端判定全员倒下 → 广播 → 对端收到且自己也已倒下时跟随，
  主机负责转发多客机场景。`Downed.Tick` 里那条"立刻真死"的即时判定删掉（会和 1.5s 确认窗打架）。
- `TriggerRealDeath` 重构成可重试状态机：
  成功判据 = `PlayerDeath` 窗口真的打开（不信 `IsDead`，因为异常常发生在开窗之前）；
  失败保留观战 + 0.6s 重试，三级兜底 = 原生 KillCharacter → 手动 `SetWindowIsOpen` →
  `SceneLoader_RL.LoadScene(Lineage, FadeToBlackWithLoading)`；
  异常用递归 `DescribeException()` 打完整 InnerException 栈。
- `TriggerRealDeath` 前先把角色 `SetActive(true)`（inactive 时 KillCharacter 内部会炸）。

**协议**：2500 → **2600**。**版本**：2.4.0 → **2.4.1**。
md5 `8f2e8787120aa83fcdc3e57d14bfdf52` / 286720B，五处一致；四实例 cache 重置。
