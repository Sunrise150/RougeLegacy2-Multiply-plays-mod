## v1.7.8：协作专属行为第一步——留尸体 + 长按 H 救援（14:02 部署）

**用户需求**：做第二步（用户确认范围=先只做救援，不动门逻辑）；无人救兜底用"血上限惩罚 + 安全救援窗口"：每次倒地血上限 -1/20，逼队友为保血上限来救；房间无怪且队友在房内时 60 秒内可自救，有怪也可强行救。

### 方案确认（动手前问过用户）
- 范围：只做救援，齐门过房这轮不做（门逻辑是"无法进房"重灾区，风险高）。
- 兜底：血上限惩罚制，不是定时自动复活、也不是自按 H 爬起。

### 关键技术调研（反编译确认）
- `PlayerController.ActualMaxHealth` 是计算属性：`≈ (ClassModdedMaxHealth + 100) * (1 + MaxHealthMod + TraitMaxHealthMod + RelicMaxHealthMod)`。
- 基类 `MaxHealthMod` 是 `protected set`，且 `InitializeHealthMods()` 会清零 → 直接改字段不可靠。
- 最终用 **Harmony postfix 补 `get_ActualMaxHealth`**：按静态惩罚栈 `HealthPenaltyStacks` 动态扣减（每次 -0.05，下限 0.4），任何时机重算都生效，救起减栈即恢复。

### 实现（新文件 CoOpRescue.cs，已登记 csproj）
- 参数集中在常量：每倒地 -5% / 上限 12 层 / 长按 H 2s / 救 human 距离 3 / 安全窗 60s / 绝对兜底 210s / 同房判定 24。
- 死亡分流：`DownedPatches.KillCharacterPrefix` 按 `Score.Style` 分流——CoOp 走 `CoOpRescue.OnLocalDown`（复用 `DownedState.GoDown` 隐藏角色+广播 downed+停物理，镜头切回自己尸体），Race 保持 `QuickRespawn`。两者都 return false 拦真死。
- 起身 `StandUp(restorePenalty)`：队友救=减一层惩罚；自救/兜底=惩罚保留。复用 `DownedState.Revive` 回满血（用新上限）+ 复位 + 原位复活 + 房间修复 + 镜头回本地。
- 救援网络：`MsgType.CoOpRescue=32`（ReliableOrdered），救人者 `NetworkManager.SendCoOpRescue(targetId)` → 主机中转 → `CoOpRescue.OnRescueReceived`（只有 targetId==本地且真倒地才起身）+ `OnRescueBroadcast`（其他端清 downed 标志）。
- 安全窗判定 `IsSafeWindow()`：尸体/队友/敌人都在 24 单位内判定；无活敌且有非倒地队友在附近 → 累计自救时间；否则暂停。
- 驱动：`DownedManager.Update` 每帧 `CoOpRescue.Tick()`（倒地走 TickDowned，活着走 TickRescuer 长按 H）。
- 断网兜底：Active=false 时 2s 自行爬起（惩罚保留），防永久躺尸。

### 踩坑/关键修复
- **冲突**：协作倒地复用 `DownedState.LocalDown=true`，而 `DownedState.Tick` 的观战逻辑有"8s 无人自动复活 / 全员倒下真死"会破坏救援 → 在 `DownedState.Tick` 的 `if(!LocalDown)return` 后加协作 early-return，观战逻辑全交给 CoOpRescue。

- 镜头：GoDown 默认切观战队友，协作不应切 → OnLocalDown 后 `DownedState.Follow(本地go.transform)` 切回尸体。

## v1.8.0：修复暂停/晚进房/丢包导致共享血量错乱（14:45 编译，部分部署）

**用户反馈**：血量同步下降已 OK；但一方按 ESC 暂停后数据不收发——主机在客机进房前把怪打到半血，客机进房看到的是满血；主机把怪打死，客机端对应怪不死、留存。

### 根因（同一缺陷两表现）
- 旧共享血量是**纯事件型**（谁打怪发伤害事件给对端）。错过那一刻事件的端永远拿不到当前血量状态：主机半血怪的伤害事件在客机进房前就发完了 → 客机本地生成满血怪；主机击杀事件发出时客机不在场/未匹配 → 客机怪留存。暂停只是放大了"错过事件窗口"。
- 不是网络真停：`NetworkManager.Update` 用 `unscaledDeltaTime`，暂停(timeScale=0)时仍在跑；但为兜底游戏可能冻结 Update 的情况，加了第二驱动。

### 修复（v1.8.0）
1. **主机权威血量快照对账**（EnemySync.cs）：新增 `MsgType.EnemyStateSnapshot=35`（Sequenced）。`HostTick()` 每 0.4s（unscaledDeltaTime）广播当前所有活怪 key→hpPct + 未过期死亡墓碑（key，TTL 8s）。挂在 NetworkManager 主机分支。客机 `ApplySnapshot(reader)` 按 key 幂等**向下校正**血量（本地明显高于权威才 SetHealth(target,false,true)，低于权威说明本地刚打伤交给事件转发收敛，不回抬）；墓碑命中则 `KillLocal` 补杀。防御畸形包（count>512 丢弃）。
2. **墓碑记录**：主机本地真实击杀（`KillCharacterPrefix`）+ 主机收到客机击杀本地补杀（`KillLocal`）都记 `_tombstones[key]=unscaledTime`；`ResetAll` 清墓碑/计时。
3. **网络泵双驱动**：`NetworkManager.Update` 逻辑提取为 `PumpNetwork()`，加 `frameCount` 守卫防重入；`Bootstrap.Tick`（挂在 `Application.onBeforeRender`）也调一次 → 暂停/Update 被冻结时仍收发。
4. 版本 1.8.0（BepInPlugin + Awake 日志）；README 功能一览/版本字符串/版本历史同步。

## v1.8.3：修复客机施法在主机端动画卡顿（16:30 编译部署）

**用户反馈**：客机做法术，主机那里法术一直卡顿状态。

### 根因（PlayerSync.RemoteAnimatorMirror.ApplyNetworkAnim）
法术是一次性动画(loop=false)。旧逻辑一次性动画**不加 age 预测**（`predN = t + (loop?age:0)`），而循环动画加了。网络包 20Hz 的 `t` 天然落后分身本地 60fps 播放进度 → `predF < curF` 判定"对端重新开始"每帧成立 → 每 0.3s(NetOneShotResyncGap) 反复 `cl.Play(hash,l,predN)` 把动画拉回旧进度 → 视觉卡顿/抽搐。

### 修复
1. 一次性动画也加 age 预测：`predN = t + age`（age 上限 0.3s，短动画 predN>1 自然不触发补播，安全）。
2. 真正"对端重新施法"改用【网络 t 回卷】：`_lastRemoteNorm[l]`/`_hasRemoteNorm[l]` 记录上次 t，`t < last - OneShotRestartGap` 才算重播；状态切换/循环层也更新这两个数组。
3. needReplay = (分身已播完 && 目标仍在播) || remoteRestarted，仍有 0.3s 节流。
4. 加节流动画诊断日志 `[ANIM] replay layer=... hash=... loop=... t=... predN=... curN=... age=... remoteRestarted=... replays/2s~N`（每 2s 一次，仅在发生重播时打）。

- 游戏未运行，五处一次性覆盖并校验一致。

**用户反馈**：角色虚空冲刺特效没展示，只看到人在空中位移（位置同步正常，特效缺失）。

### 根因（三层拦截，动画特效从触发到播放全断）
1. 虚冲残影靠 Animator 的 `Dashing_Effect` **Trigger** 驱动动画状态里的 `EffectTriggerAnimBehaviour` 播放。现有网络动画同步只传 float/int/bool + 层状态 scrub，Trigger 读不到也不传 → 分身不进特效状态。
2. 即便进了，分身 Animator 被 `PlayerSync.EnsureCloneEffectsDisabled` 每秒重申加进 `EffectManager` 全局禁用列表（本来是防分身攻击二次伤害），`EffectTriggerAnimBehaviour.OnStateEnter/OnStateUpdate` 里 `AnimatorEffectsDisabled(animator)==true` 直接 return → 残影被吞。
3. `EffectManager.PlayEffect` 生成的是动态特效对象，不在 `_fxPairs` 里，`MirrorFx` 只镜像分身自带粒子，覆盖不到。

### 修复（v1.8.4）
- 新文件 `DashFxSync.cs`（已入 csproj）。MsgType.DashFx=36（ReliableOrdered）。
- **发送端**：patch `CharacterDash_RL.InitiateDash` postfix（不用 StartDash——其 postfix 时 m_dashInProgress 因协程未首帧仍为 false；能走到 InitiateDash postfix 末尾即真冲刺），只发本地玩家，包 ownerId + isVoid（isVoid 用 `SaveManager.PlayerSaveData.GetHeirloomLevel(UnlockVoidDash)>0` 判定，因 IsVoidDashing 此刻恒 false）。
- **接收端**：主机中转(ForwardToOtherClients)；`PlayRemoteDash` 给分身所有 Animator(含子级) `SetTrigger("Dashing_Effect")` + isVoid 时 `SetBool("VoidDash",true)`，并把这些 Animator 加入 `_grace` 豁免集合(1.2s)。
- **播放放行**：patch `EffectManager.AnimatorEffectsDisabled` prefix，`_grace` 内且未过期 → `__result=false` 并 return false 跳过原方法；过期 Remove 恢复正常禁用 → 攻击二次伤害防护不失效。懒清理，无额外 Tick。
- 换场景 `DownedState.ResetAll` 联动 `DashFxSync.ResetAll()` 清豁免。纯视觉，不改伤害/判定，竞速玩法不变。

### 关键坑（编译期查不出，已规避）
- `__0`/`__result` Harmony 参数名：`AnimatorEffectsDisabledPrefix(Animator animator, ref bool __result)` 里误留一处 `__0` → CS0103，已改 `animator`。
