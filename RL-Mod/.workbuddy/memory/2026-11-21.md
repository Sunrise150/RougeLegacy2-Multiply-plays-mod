## v2.5.3 主机帧率仍低：障碍物枚举全量扫描（未修热点）

用户追问"主机画面卡顿修复了么？帧率很低"。核对：v2.5.2 已修 relay 日志刷屏，
17:23 部署的 DLL 就是该版本；但 17:16 的主机日志仍有 189 条 `HOST relayed PlayerState`
（修复前测试），且发现另一个更重的性能热点此前漏掉。

**根因**：`ObstacleSync.CollectObstacles` 原来每次调用都做 3 次
`Resources.FindObjectsOfTypeAll`（SpecialPlatform/Buzzsaw_Hazard/EarthShiftPlatformController）。
- 主机 `HostTick` 15Hz → ≈45 次/秒全 Unity 对象注册表扫描；
- 客机 `ClientApplyLate` 更是**每帧**调用 → 60fps 时 ≈180 次/秒。
这是主线程级 GC/遍历负担，足以造成明显低帧。

**修复（ObstacleSync.cs）**
- 新增 `_obsCache` + `_cacheValid`：全量枚举改为 2Hz（0.5s）刷新；
  换场景（scene.handle 变化）或换房间（room 坐标变化 >0.5）立即失效重建。
- `HostTick` / `ClientApplyLate` 把已算好的房间坐标传给 `CollectObstacles(_obsBuf, rc)`，
  不再重复调用 `GetCurrentRoomCoords()`。
- 障碍物仍是 15Hz 采样/发包/LateUpdate 覆盖，位置与 key 逻辑不变；`ResetAll()` 清缓存。
- 空场景（缓存 0 项）用 `_cacheValid` 防止每帧重扫。

**版本** 2.5.2→2.5.3，协议 2700 不变（包格式未动）。
编译 0 警告 0 错误；零依赖单测 17/17 全过。

## v2.7.0 火墙残留真因：只同步了发射，没同步"提前消失"
