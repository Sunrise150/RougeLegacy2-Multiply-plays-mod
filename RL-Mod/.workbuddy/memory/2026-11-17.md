## v1.2.1：倒地观战四大问题修复（Downed.cs）

用户报告：客机死亡观战主机 -> 主机进下一房间客机渲染不出来；客机房间怪物持续攻击尸体但不掉血；
复活后血量还是 0；角色在房间边缘掉下去（空气墙失效感）。

### 根因（反编译确认）
- **渲染不出来**：RL2 World 场景里同一时刻只有一个房间 GameObject 激活
  （BaseRoom.PlayerExit -> base.gameObject.SetActive(false)，旧房间整体停用）。
  客机本地没走过主机走的门 -> 主机所在房间在客机端是未激活的 -> 镜头跟过去=空场景。
- **复活血量 0**：倒地是 prefix 拦 KillCharacter，血量已经扣到 0；原 Revive 只 SetActive(true)，
  游戏下一帧血量检查又触发死亡 -> Revive 后立刻再倒地（也许还吃了 knockback 掉下房间边）。

### 修复
- `EnsureSpectateRoom(pos)`：每 0.5s 找观战目标所在房间（含未激活，Resources.FindObjectsOfTypeAll<BaseRoom>
  + scene.IsValid 过滤 prefab；Bounds x/y 判定容差 1m），复刻 PlacePlayerInRoom_End：
  GetSpecialPropSeed(反射) -> SetActive(true) -> InitializeSpawnControllerInstances(反射)
  -> InitializeBackgrounds(反射) -> room.SaveController.OnPlayerEnter_LoadStageData()（public）
  -> CameraController.UpdateRoomCameraSettings(new RoomViaDoorEventArgs(room, null))（public static）。
  不挪动本地玩家、不广播 PlayerEnterRoom 事件。
- `ClearEnemyAggro()`：所有 EnemyController.Target=null（setter 会 GetComponent，注意 Target!=null 才清）。
  GoDown 时清一次 + 观战中每 2s 重清（新激活房间会刷新怪并重新锁定玩家）。
- Revive：SetActive(true) -> transform.position=LastAlivePos（放回倒地原位）
  -> SetHealth(ActualMaxHealth, false, true)（ps.LocalPlayer 是 MonoBehaviour，需 as PlayerController）
  -> ClearEnemyAggro -> Follow 自己。
- _spectatedRoom 状态在 GoDown/Revive/ResetAll/TriggerRealDeath 里重置。

## v1.2.2：武器不可见 / 复活后冻住进门失效 / 断线后回不了主菜单

### 1. 客机看不到主机武器（CharacterSync.cs）
根因就在自己代码里：ApplyToClone 先 `LookCreator.InitializeWeaponLook(...)` 启用对应武器 geo，
紧接着又调 `LookCreator.DisableAllWeaponGeo(look)` 把它全关了。InitializeWeaponLook 内部第一步
本来就 DisableAllWeaponGeo，尾随那行纯属多余且致命。删除。
（武器是 SkinnedMeshRenderer：SwordGeo/SpearGeo/...，由 LookController 持有，不是独立贴图对象）

### 2. 复活后角色冻住、门不触发（Downed.cs Revive）
日志证据：复活后连续 `[SEND] Position ... vx=0.00 vy=0.00` 数分钟位置不变，之后某次坠落后才恢复。
根因：血量归零的那次伤害给角色设了 Stunned / MovementDisabled 之类的条件状态，
正常死亡流程（KillCharacter）会复位，但我们 prefix 把 KillCharacter 拦掉了 -> 状态永久残留。
Door.GetOnTriggerStayExitRoom 见到 `ConditionState==Stunned || MovementDisabled` 直接拒绝换房。
修复：
- `pc.ResetStates()`（public override，游戏自己的复位：ConditionState=Normal、停眩晕、LockFlip=false）
- 回满血后用 `pc.CurrentlyInRoom.PlacePlayerInRoom(room.transform.InverseTransformPoint(LastAlivePos))`
  放回原位 —— 这是游戏自己的高层 API，顺带完成 Corgi 射线复位（防穿地板/掉出房间）、
  房间激活、相机边界、房间事件。注意 PlacePlayerInRoom(Vector3) 参数是房间本地坐标。
- 失败时退回直接 transform.position。

### 3. 断线后无法回主菜单（NetworkManager.Stop）
日志里 Stop 流程完全正常、无任何异常、也没有 sceneLoaded MainMenu —— 说明 ESC 暂停菜单根本没打开。
WindowManager.CanPauseNow 要求 `RewiredMapController.IsMapEnabled(GameInputMode.Game)` +
WorldBuilder.State==Complete。防御：Stop 时如果 Game map 被禁用就 SetCurrentMapEnabled(true) 复位。

### 4. 附带：倒地时断线会永久躺尸
Tick 里 `if (!InSession) return;` —— 主机断线时本地还 LocalDown，角色永远隐藏。
改为 2 秒后自动 Revive("network lost")。

## v1.6.1：修复死亡复活的四个连锁 bug（14:01 部署）

**用户报障**：客机怪物两倍 / 进下一房间加载不出 / 怪物跨房间追人 / 死后全房怪物复活。

**根因（反编译 BaseRoom / GenericPool_RL 确认）**：复活路径 `QuickRespawn`/`Revive` 调 `room.PlacePlayerInRoom(localPos)`，其 `PlacePlayerInRoom_End` 会：
1. `InitializeSpawnControllerInstances()` → 每个 `EnemySpawnController.InitializeEnemyInstance()` → `GetEnemyFromPool()`：
   - 活着的怪已借出不在池 → `GenericPool_RL.GetFreeObj` 找不到 free 就 `CreateNew()` **新建一只 = 怪物两倍**
   - 死掉的怪已归还池 → 取回同一实例 `ResetCharacter()` = **死后怪物复活**
2. 新怪覆盖 `EnemyInstance` 引用 → 旧怪成**孤儿**（房间 SetActive(false) 时 OnDisable 只归还 EnemyInstance）→ 孤儿怪永不回收、一直激活 → **跨房间追人**
3. `OnPlayerEnter_LoadStageData()` 重载房间状态 + `EnterRoom`（CheckForBiomeChange/相机/触发 Score postfix）→ 与门转场竞争 → **下一房间加载异常**

**修复（Downed.cs）**：
- 新增 `RespawnInCurrentRoom(pc, go, worldPos)`：原地瞬移 + `pc.ControllerCorgi.SetRaysParameters()`（public override，等价 EnterRoom 里的射线复位协程）+ 兜底激活当前房间。QuickRespawn/Revive 全部改用它，**不再调 PlacePlayerInRoom**
- 观战激活的房间记入 `_activatedRooms`，新增 `RestoreSpectateRooms(pc)`：Revive / ResetAll / TriggerRealDeath 时关回去（玩家当前房间除外）——观战房间残留激活是跨房间怪的另一来源
- 游戏自身的 LevelManager 初始进房仍走原生 PlacePlayerInRoom，不受影响

## v1.6.2：修复真机（两台电脑）动画抽搐 + 客机复活异常（15:35 部署）

**用户报障（两台真机，之前都是单机双开没暴露）**：主机看客机分身动画一直抽搐；客机死亡后没有立即复活。

### 动画抽搐（PlayerSync.ApplyNetworkAnim）
根因：网络动画包 10Hz，TargetAnimTime 到手已落后一个网络延迟。旧逻辑每帧拿"过期目标"比较：
1. 循环状态 normalizedTime 每圈从 N.99 回卷 (N+1).0，目标小数部分先归零、分身还在 0.9x → 误判 localRestarted → **每圈 Play 一次过期时间 = 动画每圈向后跳一个延迟**（本地双开延迟≈0 所以从未暴露）
2. 漂移阈值 0.18 在真机抖动下反复越过 → Play 刷屏
修复：Interpolator 新增 AnimPacketTime；ApplyNetworkAnim 用 包到达时刻+已流逝时间 预测当前 normalizedTime（上限 0.3s）；循环态比绝对时间（单调不回卷，漂移>0.3 才对齐、最小间隔 0.5s）；一次性态保留 cloneFinished/localRestarted 但加 0.3s 最小间隔。

### 客机死亡"没有立即复活"（Downed.cs）
两个叠加根因：
1. QuickRespawn/GoDown 复活点用死亡瞬间坐标 —— 掉坑/掉刺/空中被杀时坐标在坑底/空中 → **复活即再死无限循环**，表现就是"死了站不起来"。修复：复活点改用 `ControllerCorgi.LastStandingPosition`（游戏每帧在安全层地面记录，public 只读属性），fallback 死亡坐标

1. **IsDead 没复位**：`BaseRoom.PlayerExit` 第一行 `if (playerController.IsDead) return;`。我们的 QuickRespawn/Revive 只 `SetHealth + ResetStates()`，`ResetStates` 不改 IsDead（只有 `ResetCharacter()` 才 `IsDead=false`）。倒地观战/真实死亡路径置过 IsDead 后，人就再也进不了任何门（无任何报错）。
2. **EnterRoom 会激活房间但不初始化**：`PlayerController.EnterRoom` 里 `if (!room.gameObject.activeInHierarchy) room.gameObject.SetActive(true);`，而 `EnemySpawnController.OnDisable`（房间 SetActive(false) 时）会把 `EnemyInstance=null` 并归还池。于是复活到已关闭房间 = 房间对象回来了但怪没借出（空房间）、相机没切（视角卡死）、进入事件没广播（门触发器全关）。
3. **PlacePlayerInRoom_End 会中途 throw**：顺序 `SetSeed -> InitializeSpawnControllerInstances -> InitializeBackgrounds -> OnPlayerEnter_LoadStageData -> UpdateRoomCameraSettings -> BroadcastPlayerEnterRoomEvents`，其中 `InitializeBackgrounds()` 背景池缺资源时**主动 `throw new Exception`**。一抛全断，正好是"空怪 + 视角卡 + 门全关"三连。
4. **v1.7.3 的越界兜底 `room.PlayerExit(hit)` 会与游戏自己的 Door 触发器抢转场** → 双重 PlacePlayerInRoom / 双重 SaveStageData → 相机与房间存档错乱（"再回来怪全没了"）。
5. **MapSync 是整体替换主机 StageSaveData**（含每个 RoomSaveData 的 EnemyStates/ChestStates/BreakableStates/RoomVisited/IsRoomComplete）→ 主机清完的房间在客机也变空（世界被混合）；而客机跑图时 SaveRoomState 写的是主机副本，写盘时 `RestoreForSave` 又换回 `_original`，进度直接丢。

### 修复
- `QuickRespawn`/`Revive` 增加 `pc.ResetIsDead()`（门失效的直接元凶）。
- `RespawnInCurrentRoom`：EnterRoom **之前**记 `wasActive`；若房间原本关闭 → `RoomFix.CompleteRoomActivation(room,pos,true)` 按 PlacePlayerInRoom_End 顺序补完（种子/借怪/背景/存档/相机/真实 door 广播/门触发器），每步独立 try；否则 MarkEntered（IsPlayerInRoom + 门触发器 + 相机）。
- `RoomFix` 新增 `ApplyCamera` / `FindNearestDoor` / `CountMissingEnemies` / `RequestVerify`；巡检每 0.5s：IsDead 强复位（仅 InSession、非 AllowRealDeath）、换房后 0.8s 一次性体检（相机 + 空怪补刷，最多 2 次）、门触发器自愈（进房 1s 后）、`IsPlayerInRoom==false` 补 MarkEntered、掉出房间 10m/3s 摔死。
- **删除**越界兜底的主动 `PlayerExit`，只记日志 + 重开触发器。
- `RoomFix.Apply(harmony)` patch private `BaseRoom.PlacePlayerInRoom_End(Door)` 的 **finalizer**：捕获异常后补做 LoadStageData/相机/广播/门触发器并吞掉异常（避免半初始化状态）。
- `MapSync.ResetRuntimeState(stage)`：套用主机地图后，把每个 RoomSaveData 的 `IsRoomComplete=false`、EnemyStates/ChestStates/BreakableStates/DecoBreakableStates 全设 `IsStateActive=true`（怪全在、箱子没开、破坏物完好）；**保留 RoomVisited**（小地图能看路线）。地图布局/种子/连接关系仍来自主机。

## v1.7.5：客机"无法进房间 / 返回主菜单失灵"总根因修复（23:50 部署）

**用户反馈**：客机又失灵无法进房间；同时客机点"返回主界面"没反应。

### 客机日志事实（H:/RougeLegacytransform，v1.7.4，23:38）

### 总根因（反编译 StageSaveData.cs 确认）
- `StageSaveData.m_roomSaveDataLookupTable` 是 **[NonSerialized] 私有字典**（`BiomeType → Dictionary<int, RoomSaveData>`），只有 `CreateRoomSaveDataLookupTable()/CreateAllBiomeLookupTable()`（public、幂等）会构建。
- `GetRoomSaveData()` 第一行 `m_roomSaveDataLookupTable.TryGetValue(...)` → 表为 null 直接 NRE。
- 我们 MapSync 用 BinaryFormatter 反序列化主机地图后直接 `SaveManager.StageSaveData = stage`，**没建索引表**。游戏正常读盘路径会自己建表，我们绕过了它 → 从地图同步上线起，客机所有 GetRoomSaveData 全 NRE：
  - 过门：`OnPlayerEnter_LoadStageData` NRE → `PlacePlayerInRoom_End` 在"相机切换 / 广播进入事件"之前断掉 → 门触发器没人开 = **无法进入下一个房间**（v1.7.3/1.7.4 修的门触发器/复活广播全是给这个 NRE 擦屁股）；
  - 退主菜单：`ReturnToMainMenuOptionItem` 首行 NRE → 退菜单流程中断 = **按钮点了没反应**；
  - 小地图 `MapController` 全坏。

### 修复（MapSync.cs）
- 新增 `EnsureLookupTable(stage)`：try 调 `stage.CreateAllBiomeLookupTable()` 并打日志。
- 三处赋值后统一补建：`ApplyMap`（套用主机地图）、`ReapplyAfterSave`（写盘后换回主机副本）、`Restore`（会话结束恢复客机原始数据）。
