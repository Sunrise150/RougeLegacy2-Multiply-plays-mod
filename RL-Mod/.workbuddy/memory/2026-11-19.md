## v1.9.0：主菜单原生「联机中心」入口 + 联机配置档 + 联机暂停不冻结世界（部署完成）

**用户需求**：
1. 没带 U 盘 → 本轮不部署 H 盘客机；不更新 README。
2. 弹窗（可拖动小面板）不方便 → 主菜单加原生栏入口，点进去切换界面、选存档。
3. 怀疑怪物不同步的根源是 ESC 暂停后游戏时间停了导致数据不收发 → 改进/取消暂停。

**动手前确认的方向（AskUserQuestion）**：
- 界面功能 = 完整联机中心（原生按钮 + 整屏界面，替代小弹窗）
- "选存档" = 联机配置档（保存/读取多套联机规则设置），不是游戏 Profile 槽
- 暂停 = 菜单开但世界不停（ESC 照常开菜单/能返回主界面，但不冻结游戏）

### 暂停真相（技术判断，已写进代码注释）
- 网络收发用 `unscaledDeltaTime` + `MonoBehaviour.Update`，timeScale=0 时不中断；真正被冻结的是游戏逻辑（怪 AI、死亡协程、血条、快照对账都走 scaled time）。
- 原链路：ESC → `WindowManager.PauseWhenPossible` → `GameManager.SetIsPaused(true)` → `RLTimeScale.SetTimeScale(TimeScaleType.Game, 0f)` → timeScale=0。
- 不采用"彻底禁用 ESC"（会失去返回主界面/调设置能力，用户之前抱怨过）。

### 实现（4 个新文件 + 改造）
- **PauseCompat.cs**（新）：patch `RLTimeScale.SetTimeScale` prefix，联机(`NetworkManager.Connected`)时把 `TimeScaleType.Game && value<=0` 改为 1f。IsGamePaused 仍 true → 菜单正常弹出、RewiredMap 切 Window、能返回主界面；但 timeScale 保持 1。`KeepWorldRunning` 静态开关由 BepInEx 配置 `CoOp/KeepWorldRunningWhenPaused`（默认 true）；单机未连接完全不受影响。10s 节流日志 `[PAUSE] 拦截了 N 次`；`PauseCompat.Tick` 挂 NetworkManager.PumpNetwork。
- **ConfigProfiles.cs**（新）：联机配置档。字段 = Style/Mode/全部计分值/加时/完赛宽限/重连宽限/终点Boss/IP/KeepWorldRunning。`System.Xml.Serialization` 存 `BepInEx/config/RL2MP_Profiles.xml`（JsonUtility 不在本老版 Unity 引用集，弃用）。提供 CaptureCurrent/SaveNew/Overwrite/Delete/Apply(主机载入自动 Score.BroadcastConfig + Race.HostSetTargetBoss)。上限 12 套。
- **MpHub.cs**（新）：整屏联机中心 IMGUI，4 页签——连接 / 玩法规则 / 配置档 / 说明。连接页含 IP+预设、启动/连接/停止、KeepWorldRunning 开关、Debug/倒地测试；规则页复用 ControlPanel 静态绘制；配置档页支持保存/载入/覆盖/重命名/删除；说明页含公平开局+热键。由 ControlPanel.OnGUI 转发绘制（OnGUI 必须在活组件里调）。

## v2.0.4：修复换房 ping-pong 卡死 + 客机退出拖垮主机（20:32 部署）

**用户反馈**：主机和客机都卡死；客机还出现了游戏结束后的"开发者感谢"(Credits)。

**日志实证（双方均 v2.0.3，20:27 那局）**：
1. **换房 ping-pong 死循环**：主机日志 `[ROOMSYNC] 已跟随 P1 换房 -> 房间(64,0)` / `(96,0)` **交替几十次**（543~636 行），客机同时反复 `广播过门 -> 房间(64,0) 门 side=3 num=0`（566~614 行）。原因：`ApplyTravel` 里直接 `dest.SetActive(true)+dest.PlacePlayerInRoom(door)` 把玩家放在门的触发器上，门在**之后某一帧**触发 `OnPlayerExitRoom -> BaseRoom.PlayerExit` -> 我们的 prefix 又把对面房间广播出去 -> 对方跟回来 -> 无限往返。`_applyingRemote` 只在同步调用栈内有效，盖不住延后帧。
2. **客机 PlacePlayerInRoom_End 每次必 NRE**（317/404/567/593/615 行）+"兜底加载房间存档失败"：因为绕过了原生 `BaseRoom.PlayerExit` 里的 `BroadcastPlayerExitRoomEvents`（`SaveController.OnPlayerExit_SaveStageData()` + 退房事件），目标房间 `OnPlayerEnter_LoadStageData()` 拿不到阶段数据直接 NRE。
3. **客机回主菜单把主机一起拖走**：客机 624 行 `[SCENE] 广播场景切换 -> MainMenu/FadeToBlackNoLoading (isHost=False)` -> 主机 701 行 `[SCENE] 跟随场景切换 -> MainMenu`。两端场景序列可见：Splash->Disclaimer->MainMenu->World->**MainMenu**。Boss 位图两端均 mask=00000000，与 Credits 无关；Credits 场景也没加载过（是客机对局状态被换房循环搞崩后回主菜单，用户看到的是主菜单/结束画面）。

**BaseRoom.PlayerExit 原生流程（decomp/full/BaseRoom.cs:279）**：
`BroadcastPlayerExitRoomEvents(door)`（存阶段数据 + 退房事件）-> 旧房间 SetActive(false) -> `room.PlacePlayerInRoom(connectedDoor)`（刷怪/背景/存档/相机/进入事件）。**必须先退房收尾再进房**。

### 实现（RoomTravelSync.cs 整文件重写）
1. **走原生通道**：优先在当前房间用 `FindDoorToRoom` 找一扇 `ConnectedDoor.Room == 目标房间` 的门，直接 `cur.PlayerExit(localDoor)` —— 完整原生流程，NRE 消失。只有目标不是邻居时才手动搬（且先补 `cur.BroadcastPlayerExitRoomEvents(null)` + 停用旧房）。
2. **回声时间窗**：应用远端换房后 `_suppressUntil = now + 1.8s`，窗内 `PlayerExitPrefix` 一律不广播（盖住延后帧的触发器）。
3. **限流刹车**：3 秒内超过 8 次换房判定为回声，暂停跟随 3 秒并告警。
4. **收包-应用解耦**：收包只记 `_pending`，真正传送放到 `NetworkManager.LateUpdate -> RoomTravelSync.Tick()`（一帧一次），避免在网络回调里 SetActive/跑协程重入卡死。

## v2.0.5：修复"跟随换房后掉虚空"（20:47 部署）

**用户反馈**：客机去另一个房间，主机跟随传送进去后**直接掉虚空**，然后卡死。

**日志实证（20:44 那局，注意这局 H=主机、D testing=客机）**：
- H(主机)：`[ROOMSYNC] 已跟随 P1 换房 -> 房间(64,0) 原生通道` ->

**根因**：v2.0.4 改成"走原生 PlayerExit 按门放置"，而
`Door.CenterPoint` 是 `Door.SetRoom()` 用 `room.Coordinates/Size` 算出来的；
房间若是从未激活过的（RL2 同一时刻只有一个房间激活），门的 CenterPoint/Coordinates 还是 0，
`PlayerController.EnterRoom(door)` 用它算落点就会飞到房间外 -> 掉虚空。
`PlacePlayerInRoom_Start()` 只做 `IsPlayerInRoom = true`，**不会**激活房间；
激活发生在 `EnterRoom` 里、且在算完位置之后，所以救不回来。

### 实现（RoomTravelSync.ApplyNow）
1. **改用房间出生点放置**：`dest.PlacePlayerInRoom(dest.PlayerSpawn.transform.localPosition)`，
   PlayerSpawn 是关卡设计指定的出生点（必定在实地上），不依赖门坐标。
   附带好处：不踩门的触发器，也就不会再有换房回声。
2. **补齐退房收尾**：先 `cur.BroadcastPlayerExitRoomEvents(null)`（存阶段数据 + 退房事件），
   再停用旧房、激活新房，最后放置 —— 减少目标房间 `OnPlayerEnter_LoadStageData` 的 NRE。
3. **落地自检（0.5s）**：`VerifyLanding()` 比对玩家坐标与目标房间 `Bounds`（含 3m 容差），
   不在房间里就拉回出生点并 `RoomFix.RequestVerify()`。哪怕还有极端情况也不会掉虚空。
4. 无 PlayerSpawn 的极少数房间才退回按门放置。
5. `Reset()` 一并清 `_verifyDest`。

## v2.0.6：卡顿/落点/仇恨抽搐 三项专项（21:11 部署）

**用户反馈（一台电脑双开测试）**：①画面卡顿；②跟随传送落在房间中部，不是入口；③仇恨问题——主机被怪打时正常，切到客机后"打向主机的子弹对主机没伤害"，且怪物仇恨转向客机后移动轨迹不自然、抽搐。

**根因定位**
- **卡顿**：`EnemySync.BuildKey` 每次调用都读 `SceneManager.GetActiveScene().name`。Unity 的 `Scene.name` 每次都从原生层分配新 string。位置同步在客机上是"每帧 × 每只怪"调用（60fps×50 怪≈3000 次/秒），GC 周期一来就是成片掉帧。另外每 0.4s/20Hz 都 new NetDataWriter、new List。
- **落点**：v2.0.5 用 `dest.PlayerSpawn`（关卡设计默认出生点，通常在房间中部）。
- **抽搐**：客机 LateUpdate 里 `Lerp(transform.position, 权威坐标, 0.6)` —— 把本地 AI 每帧算出的位移当成了"误差"再拽回去，AI 拉一下、同步拽一下，每帧来回抵消；而且 20Hz 离散坐标直接 lerp，没有时间轴插值，网络抖动直接变成画面抖动。
- **包体超 MTU**：墓碑 key 无限塞进一个 Sequenced 包（2048×4B），超 MTU 会被 LiteNetLib 直接丢弃 → 运行久了血量同步莫名失效 + 大包瞬时卡顿。

**实现**
1. `EnemySync`：新增 `SceneHash()` 按 `scene.handle` 缓存场景名哈希；新增 `Dictionary<EnemyController,int> _keyCache`（敌人缓存刷新时清空）→ BuildKey 从"每次都分配字符串"变成"一次字典查找"。快照 writer 复用；快照敌人数量上限 48、墓碑改**分片轮转**（每包 64 个，`_tombSkip` 轮转），保证包体稳定在 MTU 内且所有墓碑最终都送达。
2. `EnemyPositionSync` 整文件重写：
   - 15Hz，包体 key(4)+pos(12)+facing(1)+**target(1)**=18B/只，上限 48 只。
   - 主机按"到本地玩家 / 到各客机分身"的最近距离决定每只怪的仇恨目标（1=主机 2=客机），带 1.6m 黏性防抖，随包广播。
   - 客机保存前后两个采样，按 **90ms 渲染延迟做时间轴插值**（标准 netcode），网络抖动被吸收。
   - **只纠正不对抗**：这怪在追本机（target=2）→ 本地 AI 完全主导，只有偏差 >2.2m 才兜底拉回；这怪在追对面 → 画面完全由权威轨迹决定，**绝对写自维护的 Rendered 位置**（不读 transform，避免把 AI 位移算进误差），再加 dt*20 低通。
3. `RoomTravelSync`：新增 `TryGetEntranceLocal` —— 用 `RoomUtility.GetDoorCenterPoint(dest.Coordinates, dest.Size, DoorLocation(side,number))` 算入口那扇门的中心，再朝房内缩 2m 落位（只依赖房间坐标+格数，不依赖门对象是否激活，不会重演 v2.0.5 的 (0,0) 掉虚空）。注意门的**退出触发器整格在房间外侧**，落在内侧才不会被弹回上一个房间。自检失败先重试入口、再退出生点。房间表按场景缓存（`Resources.FindObjectsOfTypeAll` 不再每次换房全扫）。
4. 版本 2.0.6。

**部署**：零警告零错误，md5 `f952e946ddad8d58febe7e7c2e53ec80` / 280064B，五处一致（bin/Debug、deploy、D主实例、D测试实例、H:/RougeLegacytransform 客机）。H 缓存已备份。

**待验证**：过门后日志应为 `已跟随 P? 换房 -> 房间(x,y) 入口落位`，人站在入口门内侧；怪物不再抽搐；`[EPOS]` 日志 15Hz。

## v2.1.0（21:23–22:00）传送可靠性重写 + 分身受击盒

**用户反馈**：`传送有时候有用有时候没用`、`给我改造加受击盒吧`。

**传送为什么时灵时不灵（三处静默丢包，各只有一次机会）**
1. `Tick()` 里先把 `_pending` 清掉再调 `ApplyNow` —— 应用失败（房间还没生成 / 玩家还在加载）那个包就永远消失了。
2. `ApplyNow` 开头 `if (now < _suppressUntil) return;` —— 紧跟在上一次跟随之后的包被直接丢弃。
3. 广播只发一次；对端此刻 `CurrentlyInRoom == null`（加载中）或丢包，就再也不会有第二次机会。
   - 副作用：抑制窗 1.8s 内 `PlayerExitPrefix` 一律不广播 —— 玩家连续过两扇门时第二扇门的广播被吞，对端不跟。
   - 另一个洞：`GetAllRooms` 缓存只在"房间数量变化"时重建。换层时 Room 对象被销毁重建但数量相同 → 缓存里全是 Unity 假 null，`FindRoomByCoords` 永远找不到。

**修法（RoomTravelSync 整文件重写）**
- `_pending` 只在"成功"或"确定不可重试"时清；重试 0.25s/次、最长 4s（`MaxTries=14`）。`ApplyNow` 返回 `Success|Retry|Drop`。
- 抑制窗 1.8s→0.8s，且不再"窗内一律不广播"：窗内只吞"PlayerExit 目标 == `_suppressReturnCoords`（跟随前所在房间）"的回声，玩家刚落地又走别的门仍正常广播。
- 广播带自增 `ushort seq`，`+0.35s / +1.0s` 各补发一次；接收端按 sender 记 seq，只丢"更旧"的包，相同 seq（补发）放行。补发前校验"本地玩家还在目标房间"，防止玩家又走了还被旧包拽回去。
- 本地主动过门时 `_pending = false`（本地优先，不被重试包拉回）。
- `GetAllRooms`：缓存里出现 Unity 假 null 就重建；`FindRoomByCoords` 未命中时无条件 force 重建一次再找。
- 包格式变化：RoomTravel 增加 seq 字段（NetworkManager 收发同步改）。

**受击盒（新文件 RemoteHurtbox.cs + PlayerHurtSync.cs）**
- `RemoteHurtbox`：分身下挂 `Hurtbox` 子物体，`BoxCollider2D`(trigger) + `layer = Body_Hitbox(21)`，尺寸取真身 `PlayerController.CollisionBounds`（world Rect → 本地空间，按 lossyScale 归一化）。**不加 Rigidbody2D**：敌方 `HitboxController` 强制 `RequireComponent(Rigidbody2D)`，触发检测天然成立，少一个刚体少一份物理开销。
- 命中解析：`HitboxInfo → HitboxController → DamageObj`（`ActualDamage`，回退 `BaseDamage`）；只吃 `Enemy / EnemyProjectile / Hazard`，不做友伤。
- 节流：同源 0.3s、全局 0.1s。本地先放 `HitSparksSlash_Effect` + 分身 SpriteRenderer 闪红 0.07s（`_sprites` 缓存失效会重建）。
- 转发链路：`PlayerHurt(44)` 包 `[senderId, targetId, dmg, stun, srcX, srcY]`，ReliableOrdered，主机 `RelayToOtherClients` 中转（3 人局）。接收端 `targetId == LocalPlayerId` 才处理。
- 接收端用 `RemoteDamageObj : MonoBehaviour, IDamageObj`（数值壳）走原生 `PlayerHitResponse.StartHitResponse(dummy.gameObject, dummy, -1f, false, true)` → 扣血/暴击/伤害数字/屏幕震动/击退/无敌帧/死亡流程全部原生生效。dummy 位置设成 srcX/srcY，让原生按 x 比较算出的击退方向正确。
- 防双倍：`PlayerHitResponse.StartHitResponse` postfix 记录 `_lastLocalHurtAt`（`RemoteDamageObj` 来源不记），网络伤害到达时若 0.18s 内本地已结算过就丢弃；网络伤害之间 0.18s 去重。
- **关键坑**：不能用 `PlayerHitResponse.IsInvincible` 判无敌 —— 它在 `!RewiredMapController.IsMapEnabled(Game)`（窗口失焦/暂停菜单）时也返回 true。单机双开时非焦点窗口正好是这状态，会把所有转发伤害全拦掉。改用 `hitResponse.InvincibleTimer > 0.001f`（真无敌帧）。这可能也是"子弹打分身没伤害"的另一半原因。
- Plugin 注册 `PlayerHurtSync.Apply(_harmony)`；`NetworkManager.Stop` 清时间戳。

**依赖**：新增引用 `UnityEngine.Physics2DModule.dll`（从游戏 Managed 目录复制到 Libs，csproj 加 HintPath）。`Libs/UnityEngine.Physics2DModule.dll`。

## v2.2.0（22:51–23:40）掉虚空 / 死后攻击不停 / 法术特效残留 / 伤害落空

**用户反馈**：传送看着不错了，但①客机又掉虚空；②一方死亡后另一方攻击"没有停歇"；③持续性法术的特效在对端一直显示；④攻击没有对每个人都奏效（问是否同机测试导致）。

**证据（H 客机日志，localId=1）**
```
[SEND] Position update -> (306.88,60.77) vy=-4.74 ...
[ROOMSYNC] 广播过门 -> 房间(256,36) 门 side=0 num=1 seq=6   ← 在人已经在往下掉的时候
[SEND] ... y 60 -> 8.75  vy 恒 -38
```

主机日志：`[ENEMY] 收到伤害 key=-177130584 但本地未找到对应怪（不同步/已死）`。

**四个根因**
1. **掉虚空**：客机自己过门走原生 `PlayerExit -> PlacePlayerInRoom -> PlacePlayerInRoom_End`。`PlacePlayerInRoom_End` 里 `SaveController.OnPlayerEnter_LoadStageData()` 抛 NRE，异常直接冲出方法 → 后面的**相机、BroadcastPlayerEnterRoomEvents 全没跑**（视角卡住/门全关/房间半初始化）。我们原来只在最外层 `PlacePlayerInRoom_End` 兜，异常早就跑出去了 = 白兜。另外 `PlayerController.EnterRoom` 用 `door.CenterPoint` 算落点，房间没初始化时它是 (0,0)，人直接被放到房间外/悬空。
2. **死后攻击不停 / 法术特效不消失**：`PlayerSync.MirrorFx()` 把**本机玩家**身上的 ParticleSystem 状态镜像到分身上（`lp.isEmitting → cp.Play()`）。本机持续性法术结束后特效对象被回收成 null，旧代码 `lp == null → continue`，分身那份就永远喷下去。攻击同理，看着像"不停歇地攻击"。另外发送端把**层权重为 0 的层**也按原样发（hash + 旧的 t=0），远端 `cloneFinished && targetStillPlaying` → 每 0.3s 补播一次 → 分身无限重复攻击动作。
3. **伤害落空**：key = 场景+刷怪序号+类型+等级。客机房间初始化不完整 → 序号整体漂移 → key 对不上 → 伤害被静默丢弃。
4. 同机测试：两个窗口抢键盘/抢 GPU，输入会串、帧率互相拖累，会放大①②③，但不是④的原因。

**修法**
- `RoomFix`：
  - 新增 `RoomSaveController.OnPlayerEnter_LoadStageData` **finalizer 就地吞异常**（打完整 `ex.ToString()` 含栈，5s 节流），让 `PlacePlayerInRoom_End` 后面的相机/进入事件照常跑。外层 finalizer 保留作二道保险。
  - 新增 `PlayerController.EnterRoom(BaseRoom,Door,Vector3)` **postfix 落点自检**：脚下 12m 内 `Physics2D.RaycastAll` 没有非触发器/非角色碰撞体 → 判定悬空，立刻用 `TryFindSafeSpot` 救回（门内侧 2.5m → 房间中心 → 房间根，取第一个有地面的）。只在 `DownedState.InSession && room is Room` 时生效，单机/城堡不碰。
  - 掉出房间从"3 秒后摔死"改成**0.5s 内救援**：`pos.y < Bounds.min.y-1.5` 或离房间 3m 以上即调 `RescueFromVoid`（设位置 + `ControllerCorgi.SetLastStandingPosition` + `SetVelocity(0,0,false)` + `ResetStates`），4 次都救不回才 KillCharacter。
- `PlayerSync`：
  - 发送端：`anim.GetLayerWeight(l) < 0.02` 的层（l>0）hash 发 0，远端直接跳过不再补播残留攻击状态。
